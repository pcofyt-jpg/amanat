# AMANAT на GitHub Pages + Supabase

Всё делается в браузере, программировать не нужно. Займёт около 20 минут.

## Что в архиве

| Файл | Зачем |
| --- | --- |
| `index.html` | само приложение |
| `supabase.sql` | база данных и правила доступа |
| `manifest.webmanifest`, `icon-192.png`, `icon-512.png` | значок, чтобы добавить приложение на экран телефона |

## 1. База данных в Supabase

1. Зайдите на supabase.com → **New project**. Название — `amanat`, регион — **Central EU (Frankfurt)**, придумайте пароль базы и сохраните его.
2. Когда проект создастся: слева **SQL Editor** → **New query** → вставьте всё содержимое файла `supabase.sql` → **Run**. Должно появиться «Success».
3. Слева **Authentication** → **Sign In / Providers** → **Email**: выключите **Confirm email** (иначе каждому придётся подтверждать почту) → **Save**.
4. Слева **Project Settings** → **API** (или **Data API**). Скопируйте:
   - **Project URL** — вида `https://abcdefgh.supabase.co`
   - ключ **anon public** — длинная строка, начинается на `eyJ...`

> Ключ **service_role** никогда никуда не вставляйте — он даёт полный доступ к базе.

## 2. Вставить ключи в приложение

Откройте `index.html` любым текстовым редактором (на компьютере — Блокнот, VS Code). В самом начале найдите блок **НАСТРОЙКИ** и замените две строки:

```
SUPABASE_URL:"https://abcdefgh.supabase.co",
SUPABASE_ANON_KEY:"eyJ...ваш ключ..."
```

Сохраните файл.

## 3. Выложить на GitHub Pages

1. На github.com → **New repository** → название `amanat` → **Public** → **Create repository**.
2. **uploading an existing file** → перетащите все 5 файлов (кроме этой инструкции) → **Commit changes**.
3. **Settings** → **Pages** → в **Branch** выберите `main` и папку `/ (root)` → **Save**.
4. Через 1–2 минуты сверху появится адрес вида `https://ваш-логин.github.io/amanat/`. Это и есть приложение.

Репозиторий публичный, поэтому код виден всем. Это нормально: ключ anon public рассчитан на это, а данные защищены входом по паролю и правилами доступа в базе.

## 4. Первый вход и перенос данных

1. Откройте адрес приложения → **Регистрация** → ваш email и пароль. **Первый зарегистрированный становится администратором** — поэтому регистрируйтесь первым.
2. В старой версии на claude.ai: вкладка **Доступ** → **Полная копия с фото (JSON)** → сохраните файл.
3. В новой версии: вкладка **Доступ** → **Загрузить копию (JSON)** → выберите этот файл. Клиенты, сделки, платежи, займы и фото перенесутся. Журнал начнётся заново.

## 5. Добавить друга

1. Отправьте ему адрес приложения — пусть зарегистрируется. Он увидит «Ожидайте доступа».
2. У вас во вкладке **Доступ** он появится с пометкой «новый» → выберите роль **Владелец** и подпишите имя.
3. Когда все нужные люди зарегистрировались: Supabase → **Authentication** → **Sign In / Providers** → выключите **Allow new users to sign up**. Посторонний даже по ссылке больше не зарегистрируется. Но и без этого новый человек ничего не увидит, пока вы не выдадите ему роль.

## 6. На телефон

Откройте адрес в браузере → **Поделиться → На экран «Домой»** (iPhone) или **⋮ → Добавить на главный экран** (Android). Появится значок AMANAT.

## Важно знать

- **Бесплатный Supabase засыпает**, если в приложение не заходить 7 дней. Тогда зайдите на supabase.com и нажмите **Restore project** — данные не пропадут.
- **Резервные копии** на бесплатном тарифе Supabase не делает. Раз в месяц сохраняйте копию во вкладке **Доступ** — приложение само напомнит.
- **Место:** бесплатно 500 МБ. Фото сжимаются до ~200 КБ, этого хватит примерно на 2 000 фото и много лет записей.
- **Обновить приложение:** замените `index.html` в репозитории на новый (не забудьте снова вставить ключи). Данные в базе останутся.
- **Персональные данные:** серверы Supabase находятся за пределами России. Если хранить паспорта клиентов, уточните у юриста требования 152-ФЗ.

## Если что-то не работает

| Что видно | Что сделать |
| --- | --- |
| «Нужна настройка» | ключи в `index.html` не вставлены или вставлены с ошибкой |
| «Неверный email или пароль» | проверьте раскладку; пароль можно сбросить в Supabase → Authentication → Users |
| После входа пусто, «Ожидайте доступа» | администратор должен выдать роль во вкладке «Доступ» |
| Не сохраняется, ошибка доступа | скорее всего, файл `supabase.sql` выполнился не полностью — запустите его ещё раз |
